## Admin UX Features Shipped — April 28, 2026 (afternoon session)

### 1. Capacity Override (Extra Spots Clicker)
- Admin class modal now has `[−] X extra spots [+]` clicker
- Per-day overrides stored in `class_capacity_overrides` table (date + classId)
- Member schedule reflects updated capacity in real time
- Full class (e.g. 10/10) → add spots → shows available again to members
- Floors at 0, can't go negative

### 2. Waitlist Visibility in Class Modal
- Admin class modal now shows **Waitlist** section below Confirmed Attendees
- Populated from server via JOIN on bookings where status='waitlist'
- Section auto-hides if no one is waitlisted
- Cancel/manage buttons present for waitlisted members

### 3. Clickable Member Names in Class Roster
- Registered members: name shown in red, underlined, clickable → opens member profile modal
- Non-registered (walk-ins/guests): name in muted gray, not clickable, tooltip says "Not a registered member"
- Server does SQL JOIN to attach `member_id` to each booking row (no client-side lookup race)
- `openMemberProfile()` falls back to direct `/api/admin/members/:id` fetch if `_allMembers` not loaded
- Member profile modal moved outside `view-members` div so it renders from any tab

### 4. Attendee Row Alignment Fix
- Buttons (Attended / Reschedule / Cancel) now in single horizontal row per attendee
- Wrapped in flex div to fix `<td>` display inconsistencies across browsers
- `flex-wrap: nowrap` prevents stacking

### Key Bug Fixes
- `member-profile-modal` was nested inside hidden `view-members` div → modal opened but invisible from Calendar tab
- `_allMembers` fetch was async race with modal render → fixed by server-side JOIN
- `db.prepare()` vs `dbRaw.prepare()` distinction — always use `dbRaw` for direct better-sqlite3 calls
