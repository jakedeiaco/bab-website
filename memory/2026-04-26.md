**1. Admin portal — calendar buttons on booking confirmation**
- Bug: admin booking success only showed "✓ booked" with no calendar options
- Fix: added both 🔴 Google Calendar and ⬛ Apple/Outlook (.ics) buttons to admin booking confirmation modal
- Member portal already had both; admin was missing them entirely

**2. Staff notification email — Apple/Outlook calendar button**
- Bug: staff copy of booking confirmation email (to schedule.bayareaboxing@gmail.com) only had Google Calendar button
- Fix: added Apple/Outlook (.ics) button to staff email as well
- Deployed same session

**3. Admin calendar — sticky day header**
- Jake requested: day column headers (MON Apr 27, TUE Apr 28…) should stick when scrolling to PM classes
- Multiple iterations: pill nav removed, day headers re-pinned inside calendar container
- Final fix: dynamic JS offset calculation — measures actual pixel heights of site header + tabs + week nav bar at runtime, sets `top` exactly so there's zero gap
- Pill nav (secondary misaligned bar) permanently hidden on admin

**4. Member portal stats badges — timezone + attended logic bug**
- Jake's profile (Miles Delacol, Part-Time): showed 0 Upcoming / 1 Attended / 5 Cancelled but cycle showed 4/4 used — inconsistent
- Bug 1: `today` was calculated in UTC. At 6:33 PM Pacific = April 27 UTC. Confirmed bookings on Apr 26 fell through — not "upcoming" (past in UTC) and not "attended" (no kiosk check-in). Counted toward 4/4 used but invisible in badges.
- Bug 2: "Attended" only counted kiosk PIN check-ins (`attended = 1`). Most real members never use kiosk. Fixed to count all confirmed bookings on past dates regardless of kiosk scan.
- Fix: switch `today` to Pacific time; redefine "attended" as confirmed past bookings
- Expected result after deploy: 4 Attended, 0 Upcoming, 5 Cancelled, 4/4 — all consistent

### Freeze Bug Fix (8:20 PM)
- Root cause: `/api/admin/members/:id/freeze` was calling `db.prepare()` but `db` is the wrapper module, not raw SQLite — instant 500 error
- Fix: switched to `dbRaw` (better-sqlite3 direct instance), same pattern as rest of server.js
- Also fixed: freeze UI now shows current expiry date, no confirm() dialog (was being blocked on mobile), profile auto-refreshes after freeze
