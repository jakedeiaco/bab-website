## Schedule Page Debug Session (afternoon, April 13)

### Root cause of all mobile issues
1. **PWA service worker** cached old `/api/schedule` error response (`{ error: 'Login required' }`). Persisted through cache clears. Required explicit SW unregister.
2. **Root URL redirect** was `/member.html` — everyone got sent to login instead of schedule
3. **Two competing agenda containers** (`#view-agenda` vs `#mobile-agenda`) caused blank content
4. **`isMobilePortrait` at 768px vs `isCompact` at 960px** — mismatched breakpoints caused wrong layout path
5. **`buildMobileDayNav` overwrote entire `#mobile-day-nav` innerHTML** including arrows
6. **`selectMobileDay` called `renderMobileAgenda`** which rendered into `#mobile-agenda` (hidden inside `#view-calendar`)

### Final working state (deployed ~6:40 PM)
- Schedule is **public** — no login required to view
- Root URL redirects to `/index.html` (not `/member.html`)
- **Single-day view** with ← → arrows stepping through days
- ← → arrows call `shiftMobilePrev/Next` (day step) not `changeWeek`
- `buildMobileDayNav` just calls `updateMobileDayLabel()` — shows current day name
- `renderAgenda` uses `mobileDayStart` consistently
- `selectMobileDay` sets both `mobileDayStart` and `mobileDayIdx`, calls `renderAgenda`
- `_mobileClasses` starts as `null` (not `[]`) — prevents early empty render
- Null-safe references for `week-label`, `btn-prev`, `tab-btn-lookup` (removed from HTML)

### PWA lesson learned
Service workers cache API responses. When `/api/schedule` returned 401 error, SW cached it. Future deploys fixed server but phone kept getting cached error. Don't use SW for gym schedule app — benefit (offline) doesn't outweigh risk. Simple home screen shortcut is better than full PWA.

### Key decisions
- **No PWA** — shelved permanently unless done with proper cache invalidation
- **Schedule public** — no login wall; booking requires login
- **Single-day mobile view** — cleaner than pill strip, works on all screen sizes
